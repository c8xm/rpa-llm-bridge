# 企业内部接入影刀 RPA 与智能体的落地方案

> 读者：你自己的技术负责人、IT 运维、信息安全、财务/业务 Owner。
> 目标：让"影刀负责动手、智能体负责判断"这条链路，能在企业内网合规、可审计、可回滚地上线。
> 结论先行：**技术上已经具备（本仓库 v2.0），卡点从来不是代码，而是权限、账号、网络和评审。**

---

## 0. 一页纸结论

| 问题 | 答案 |
|---|---|
| 需要改代码吗 | 不需要。配 `YINGDAO_API_BASE` + AccessKey，注册 MCP 或打网关即可 |
| 谁必须点头 | 影刀管理员（应用授权）、IT（机器与网络）、安全（数据与凭证）、业务 Owner（流程责任） |
| 第一个可交付物 | 单机 PoC：一条真实流程被自然语言触发，跑完出结果，全程有审计 |
| 最大技术风险 | 机器人并发数 = 你的物理上限，不是代码上限 |
| 最大组织风险 | 用个人账号跑机器人，人一离职流程全停 |
| 上线判据 | 连续 2 周成功率 ≥ 98%，失败可定位到具体环节，回滚 < 5 分钟 |

## 1. 角色与职责（先分工，再动手）

| 角色 | 提供什么 | 不做什么 |
|---|---|---|
| 业务 Owner | 流程清单、验收标准、异常处理规则 | 不碰服务器 |
| 影刀管理员 | 应用发布与授权、AccessKey、机器人账号、客户端管理 | 不写提示词 |
| IT 运维 | 服务器/虚拟机、服务化、网络策略、监控接入 | 不改业务逻辑 |
| 信息安全 | 数据分级、日志留存、凭证保管方式、评审结论 | 不决定业务流程 |
| 你（集成方） | 网关与 MCP 服务、提示词、审计口径、故障定位 | 不代替业务确认"这一步对不对" |

> 一句话分工：**业务定"做什么"，影刀定"怎么点"，你定"怎么问、怎么记、怎么失败"。**

## 2. 目标架构（按公司网络形态选一种）

### 2.1 形态 A：内网 + 受控出网（最常见）

```
[影刀机器人机 ×N]                 [集成服务器]                    [出网]
  ShadowBot 客户端   ──HTTP──▶  agentrpa-bridge gateway  ──▶  codex / dsh / 豆包 API
  （机器人账号登录）              （内网 IP，仅 8765）              （经企业代理）
        ▲                              │
        │ 影刀开放 API（HTTPS 出网）    └─ 审计 jsonl → SIEM
        └──────────────────────────────┘
```

- 网关只监听内网，前置 Nginx 做 TLS + IP 白名单。
- 机器人机不需要任何模型 key；key 只在集成服务器上。
- 影刀开放 API 需要出网（或走正向代理），把它加进白名单。

### 2.2 形态 B：完全隔离内网（无外网）

```
[影刀机器人机] ──▶ [网关] ──▶ [内网模型：vLLM / 私有化 DeepSeek / one-api]
                     └──▶ [内网 codex / dsh 节点，模型指向内网端点]
```

- 后端用 `kind="openai"` 指内网 `base_url`；或让 codex/dsh 的模型配置指向内网端点。
- 代价：模型能力下降，提示词要更"结构化"（少让模型自由发挥，多给枚举和格式约束）。

### 2.3 形态 C：智能体反向驱动影刀（MCP 形态）

```
[WorkBuddy / Codex / Claude] ──MCP(stdio)──▶ yingdao_mcp_server.py ──HTTPS──▶ 影刀开放 API
```

- 适合"人对着助手说一句话，触发一条既有流程"。
- 需要给每个使用者配一份 `mcp.json`（`scripts/export_mcp_config.py` 可批量生成）。

## 3. 开干之前：向公司要这 6 样东西

1. **影刀企业版权限**：能进控制台、能发布应用、能创建 AccessKey。
2. **应用授权**：把要跑的应用授权给这个 AccessKey（缺这步 `startJob` 必报无权限）。
3. **机器人账号**：专门的服务账号登录 ShadowBot 客户端，**不要用个人账号**。
4. **机器**：① 影刀机器人机（装客户端）；② 集成服务器（跑网关，2C4G 起步）。
5. **网络策略**：机器人机 → 集成服务器 8765；集成服务器 → 影刀开放 API 域名；→ 模型端点/代理。
6. **安全评审入口**：数据分级结论（哪些字段不许出内网）、日志留存期限、凭证保管方式（建议 Vault/KMS/凭据管理平台）。

拿不到第 2、3 条就先别开工——这两条是企业接入 90% 的延期来源。

## 4. 四个阶段（每阶段都有明确出口）

### P0 · 单机 PoC（1 周）

**目标**：证明"一句话触发一条真流程，结果能回来，日志有痕迹"。

动作：

```powershell
# 集成服务器
python examples\reverse_demo.py                       # 先证明代码链路通（假影刀）
$env:YINGDAO_API_BASE = "https://api.yingdao.com"     # 换成真地址
$env:YINGDAO_ACCESS_KEY_ID = "ak_xxx"
$env:YINGDAO_ACCESS_KEY_SECRET = "sk_xxx"
python agentrpa_bridge\yingdao_mcp_server.py --selftest
```

```python
# 或者用网关方向：让影刀流程调智能体
答案 = ab.ask_agent("这张单据按 13% 还是 9%？只返回数字", agent="llm", timeout=60)
```

出口条件：

- [ ] `rpa_list_apps` 能列出公司应用（说明签名与路径对上了）
- [ ] `rpa_start_job` 能跑完一条真实流程并拿到输出
- [ ] 审计日志里能看到这次调用（tenant / flow / 耗时 / 指纹）
- [ ] 失败时能看到可读错误，而不是超时

> 这一步最容易卡在签名和路径：`yingdao_api.py` 的 `DEFAULT_PATHS` 与 `sign()` 是默认值，
> 按控制台文档改这两处即可。改完把真实值提交进仓库配置。

### P1 · 单产线灰度（2–4 周）

**目标**：一条真实业务线（如发票、对账）用起来，人工兜底还在。

动作：

- 网关配 `AGENTRPA_TOKENS`（一产线一 tenant），`AGENTRPA_ALLOW_ANON=0`
- 开启企业护栏（见第 6 节）：应用白名单、审批清单、并发上限、幂等窗口
- 每个流程埋 `meta.flow` / `meta.batch`，用审计做日报
- 失败路径走人工复核队列，不允许"静默重试三次然后消失"

出口条件：

- [ ] 连续 2 周成功率 ≥ 98%
- [ ] 失败 100% 可定位到"哪一步、哪个输入、哪个后端"
- [ ] 业务方确认：错单率不高于人工
- [ ] 回滚演练通过（改 `agent` 为 `llm` 或停服务，< 5 分钟）

### P2 · 网关集群 + 多流程（1–2 个月）

动作：

- 网关 2 台 + Nginx 负载均衡；`/healthz` 接监控，`/metrics` 接 Prometheus
- 流程模板化：一条流程 = 一个 Recipe/YAML + 一份提示词 + 一份验收用例
- 按后端分流：短判断用豆包/llm，长任务用 dsh，要动工具用 codex
- 审计进 SIEM，按 tenant/flow 出周报

出口条件：

- [ ] p95 延迟与失败率有基线，超阈值告警
- [ ] 单点故障演练：杀掉一台网关，业务无感
- [ ] 新增一条流程 ≤ 0.5 人日

### P3 · 规模化治理（持续）

- 流程目录与责任人清单（谁负责哪条流程、坏了找谁）
- 提示词版本化（改提示词 = 走变更，不然后果不可复现）
- 成本看板：token/单量、机器人占用率、失败重跑率
- 每季度做一次"这条流程还需要 agent 吗"的复盘（有些判断用规则更便宜）

## 5. 三个关键设计决策（评审时会被问）

**① 为什么不让影刀直接调模型 API？**
凭证会散落到每台机器人机；没有并发闸门，一个死循环能把额度打穿；没有统一审计。
网关把这三件事收敛到一处。

**② 为什么不可逆动作不交给 agent？**
"提交/付款/删除"一旦由模型直连，责任无法界定。本项目的边界是：**agent 只产出建议值，执行仍走影刀既有审批节点**。
（v0.1 内核的 `hitl` 暂停就是同一思路。）

**③ 为什么按 tenant 限速而不是全局？**
全局限速会让一个刷数据的流程拖垮所有产线；按 tenant（≈产线）隔离，坏的那条先疼。

## 6. 企业护栏（v2.1 起内置）

配置在反向 MCP 进程（`yingdao_mcp_server.py`）上：

| 变量 | 作用 | 建议 |
|---|---|---|
| `YINGDAO_ALLOWED_APPS` | 应用白名单，逗号分隔 | 生产必填，只放已评审的应用 |
| `YINGDAO_APPROVAL_APPS` | 需人工审批的应用 | 涉及资金/对外发送的流程 |
| `YINGDAO_MAX_PER_APP` | 单应用并发上限 | = 该应用可用机器人数 |
| `YINGDAO_IDEMPOTENCY_TTL` | 幂等窗口（秒） | 900；同参重复提交返回原 jobId |

行为：

- 白名单外的应用：`rpa_start_job` 直接拒绝，不产生任务。
- 审批清单内的应用：必须带 `approved_by`（审批人工号），否则返回 `requires_approval`。
- 并发满：返回 `busy`，不排队、不堆积（RPA 侧自行退避）。
- 同参数在窗口内重复提交：返回**同一个 jobId**，`deduplicated: true`，不会重复跑。

## 7. 网络与安全清单

| 项 | 要求 |
|---|---|
| 端口 | 仅 8765（网关），仅内网；管理面不暴露公网 |
| TLS | 生产必须；自签证书由 IT 统一签发 |
| 出网 | 影刀开放 API 域名、模型端点/代理，加白名单 |
| 凭证 | 网关 token 存配置中心；模型 key 存 KMS/Vault；影刀 Secret 只存反向 MCP 机器 |
| 日志 | 审计 jsonl 留存 ≥ 6 个月，接 SIEM；不含原文单据 |
| 数据 | 客户名/身份证/银行卡等字段不进 prompt（用 ID 或脱敏值），必要时先本地替换 |
| 账号 | 机器人账号独立、可轮换；离职流程里必须包含"回收机器人账号" |

## 8. 容量与成本（先把账算清）

**瓶颈是机器人数量，不是服务器。**

- 单次 agent 调用 3–15 秒；一条流程通常 1–3 次调用。
- 若公司有 5 台机器人、每单 2 次调用、每次 8 秒 → 理论峰值 ≈ 5 单/8 秒 ≈ 37 单/分钟。
- 网关并发设 `min(机器人数量, 模型 QPS 上限)`，不要按服务器 CPU 设。

成本公式：

```
月成本 ≈ 单量 × 每单调用次数 × 单次 token × 单价
```

先用 `llm`（便宜）跑判断类任务，只有需要工具/长推理时才升级到 codex/dsh。

## 9. 应急与回滚

| 场景 | 动作 | 影响 |
|---|---|---|
| 模型服务故障 | 流程 `agent` 改为 `llm` 或关闭 AI 分支 | 退回人工，不阻塞 |
| 网关故障 | Nginx 摘除节点；单机则重启服务 | 秒级中断 |
| 某流程失控（狂刷） | 该 tenant 的 token 摘掉 / 限速调 0 | 只影响该产线 |
| 影刀侧异常 | 白名单摘掉对应应用 | 该应用立刻不可触发 |
| 提示词改坏 | 回滚 prompt 版本（必须版本化） | 立即生效 |

## 10. 评审必答题（提前准备好答案）

1. **数据会不会出内网？** 只发必要字段；模型可换内网端点；审计不留原文。
2. **谁能在生产跑流程？** 只有持 token 的服务；token 按产线分发、可单独吊销。
3. **出错谁负责？** 建议值由 agent 出，执行与审批仍在影刀既有节点，责任链不变。
4. **能不能不装 Python？** 可以，影刀侧用「HTTP 请求」节点直接打网关。
5. **离线能不能用？** 能，形态 B：模型换内网 vLLM，codex/dsh 指向内网端点。
6. **日志留存多久？** 按公司要求配置，默认按天切、可接 SIEM 长期留存。
7. **模型胡说怎么办？** 输出强约束（只返回数字/枚举/JSON Schema）+ 校验不过就转人工。
8. **要不要给每个员工发 key？** 不要。员工通过 WorkBuddy/助手用 MCP，凭证在服务侧。
9. **会不会拖慢现有流程？** 只在下判断的节点加一次调用；超时即降级到规则/人工。
10. **怎么证明有用？** P1 出口指标：成功率、单均耗时、人工复核率、错单率对比。

## 12. 常见否决理由与应对

| 否决理由 | 应对 |
|---|---|
| "AI 不可控" | 输出强约束 + 校验 + 失败转人工；agent 不碰不可逆动作 |
| "数据不能出去" | 形态 B 内网模型；或只发脱敏字段；审计不含原文 |
| "多一套系统维护成本高" | 零第三方依赖、单文件 SDK、一个 `/healthz`；不新增数据库 |
| "影刀已经能跑，为什么要 AI" | 只替换"判断该填什么"的环节，减少人工回填与错单，不替换执行 |
| "出了事谁背" | 责任链不变：agent 建议、影刀执行、人审批，三段都有日志 |
